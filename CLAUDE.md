# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Azaleaporten: a free, adventure/RPG-themed practice app (matematik, svenska, engelska) for school kids, hosted on GitHub Pages at `https://andrejohanssonlindh.github.io/azaleaporten/`. No backend: all progress lives in the browser's `localStorage` on each device. UI text, comments and many identifiers are **Swedish**; keep new user-facing text Swedish and child-friendly.

The full roadmap is `../PLAN.md` (outside the repo, because it mentions private details). Phases 1–4 are done (platform, Tidstornet, loot/gear, the learning loop), plus all of Talbergen (six areas and the region boss), all of Betongbukten (seven skateparks and the region boss), all of Västerön (engelska, five areas and the region boss), all of Robotön (programmering, five areas, the region boss and Kublabbet, a Rubik's cube area), all of Ordskogen (svenska, five areas and the region boss) and the village from Phase 5. **Diagramdalen** (statistik, seven areas and the region boss), and **Kompassön** (geografi) is open with all six areas and its region boss (plans in `../PLAN.md` §14f/§14g). **Current status and the next mission are in `STATUS.md`. Read it first.**

## Commands

```sh
npm run dev          # dev server (http://localhost:5173/azaleaporten/)
npm test             # unit tests (Vitest, tests/*.test.ts)
npx vitest run tests/storage.test.ts   # one test file; add -t "<name>" for one test
npm run e2e          # Playwright (e2e/*.spec.ts); builds and serves on :4173 (reuses a running server!)
npm run typecheck    # tsc (TypeScript 7)
npm run build        # typecheck + production build to dist/
npm run pack:encrypt # encrypt ../privat/familjepaket → public/packs/familj.enc
npm run icons        # regenerate PWA icons from public/favicon.svg
```

Pushing to `main` runs `.github/workflows/deploy.yml`: test → build → deploy to Pages. Failing tests block the deploy.

## Hard rules

1. **The repo is public. Never commit real names** (kids, teachers, street, school). A pre-commit hook (`.githooks/pre-commit`, enabled by `npm install`/`npm run setup-hooks`) blocks words listed in `../privat/forbjudna-ord.txt`. Test data uses `Hjälte1`, `Hjälte2`. Kids type their own names in the app; names exist only on their device.
2. **Teacher-boss content is only ever committed encrypted** (`public/packs/familj.enc`). Plaintext lives in `../privat/familjepaket/`. A JS password check alone would be readable by anyone, so the gate really decrypts (PBKDF2 + AES-GCM, `src/platform/gate/crypto.ts`).
3. **Progress is sacred.** Every stored record has `v` and goes through `loadRecord`/`saveRecord` (`src/platform/storage/record.ts`):
   - bumping a record's `version` requires a migration `migrations[oldV]` **and** a test with a fixture of the old format
   - migrations run step by step, a backup is taken first, and the result is merged over defaults, so new fields only need a default
   - a failed migration or data from a newer app version makes the record read-only rather than overwriting it
   - never rename or reuse ids (region/area/boss ids, skill ids, item ids, error tags, class/animal ids); retire them instead
   - don't drop a field in the same release that stops using it
4. **Learning integrity:** loot, stats and class perks never change what counts as correct, reveal answers, skip questions, or lower thresholds/stars. They only affect boss-fight feel, rewards and cosmetics.
5. All storage keys go through `kv` (`src/platform/storage/kv.ts`), which prefixes `azaleaporten:`. Every repo on the same github.io account shares one origin, so the prefix matters.

## Architecture

- **Preact + @preact/signals, Vite 8, TS 7.** Preact 11 does **not** add `px` to numeric inline styles; write `${n}px`.
- **Routing:** a hash router in `src/state.ts` (`go('karta')` → `#/karta`), because Pages has no SPA fallback. `src/app.tsx` picks the screen:
  - the gate if not opened or `#/porten`
  - `vuxen`, `ny`, `hjaltar`, `gard`
  - otherwise the map
- **State:** UI state lives in signals in `src/state.ts`. Persisted data is read synchronously from storage on render; call `touch()` after writing so views re-render. Every component that reads storage must itself read `dataRev.value`: `@preact/signals` skips re-rendering a child whose props didn't change, so a child that only gets `hid` would otherwise show stale data. `src/session.ts` handles selecting or leaving a hero (`enterHero` returns the previous visit, which drives Mästare Kastanj's greeting in `src/platform/greeting.ts`).
- **Storage layout** (see `src/platform/profiles.ts`):
  - `meta` (hero ids, last hero)
  - `h:<uuid>:profile` (name, animal, color, heroClass, grade, settings)
  - `h:<uuid>:hero` (xp, level, kastanjer, blad, tips already shown, tokens, arena rank, storm steg, cave depth…)
  - `h:<uuid>:inventory` (items, equipped, chests), `h:<uuid>:wardrobe` (cosmetics owned/worn)
  - `h:<uuid>:andrad` (when the hero's progress last changed; bumped by every `saveRecord` under `h:<id>:` except `profile`, via `onRecordSaved`)
  - `gate` (unlock key; excluded from backups and exports)
  - `backup:<iso>` (automatic snapshots, the last 3 are kept)

  Hero ids are UUIDs, never names.
- **Gate:** `src/platform/gate/gate.ts` fetches `packs/familj.enc`. If it is missing, the gate is just a button, and generic personas are used. Otherwise the password is needed once per device; the derived key is stored, and the salt is kept stable by the tool so pack updates don't re-lock devices. A boss = public mechanics + a swappable persona: `personaFor()` in `src/content/bosses.ts` picks the pack persona (grade-specific first), else the generic one.
- **The island:** the map (`src/shell/IslandMap.tsx`, a hand-drawn SVG) is the start screen. Tapping a place opens its page:
  - Azaleabyn (`#/by`, the village with the buildings, including Azaleagården `#/gard`)
  - Övningsängen (`#/ovning`, review runs where Glömskans dimma lies, else a repeat of the last thing played)
  - Uppdragstavlan (`#/uppdrag`, daily quests, streak) and Biblioteket (`#/biblioteket`, the child's own statistics)
  - regions (`#/region/<id>`)
  - fog spots and the dotted islands are reserved for future subjects

  Regions and areas are defined in `src/content/world.ts`, with recommended grades only (never locks). Betongbukten (geometry) uses Malmö skateparks as levels. `src/content/heroes.ts` has animals, colours and classes.
- **Adventure model** (`src/platform/rpg/`):
  - an area (`AreaDef`) is a list of eras with a path of stage and boss nodes (`types.ts`); each node unlocks when the previous one is done
  - a game is just a question factory, `GameModule` = `makeQuestion(spec, rng)` + `skillOf(q)` + `specsForSkill(skill)` + `errLabel(tag)` + a Preact `View` that runs open → fixing → done and reports only the first answer
  - `AreaDef.texts` holds the area's result-screen words; non-klocka areas get a generic "Öva fritt" (`src/shell/LabbView.tsx`)
  - the platform owns everything else in `progress.ts`:
    - stage runs are exactly 10 questions; 9 right = ★, 10 = ★★, 10 under `thrMs` with no hint = ★★★
    - practice runs are 5 questions; review runs (`kind: 'review'`, `REVIEW_NODE`) are 5 questions on due skills, one skill per question fixed at start
    - boss fights have HP = correct answers needed and hearts = 3 (+1 riddare); every other boss question targets its `trap`
    - XP and kastanjer
    - the event log
  - a run is saved after every answer, and questions are regenerated deterministically from `seed + index`, so a reload resumes the same question
  - all numbers live in `balance.ts`: no currency per answer, and 30 minutes a day after which no more kastanjer
  - `src/content/areas.ts` registers playable areas (`PLAYABLE[id] = { def, load }`). Game code is **lazy-loaded**: only the `def` (data) is in the main chunk, and anything needing the `GameModule` gets it via `loadGame(id)` or the `useGame(id)` hook + `<Loading>` (`src/shell/useGame.tsx`). Never import a game's `index`/`logic` statically from shell or platform code, or it lands back in the main chunk (content files may only `import type` from logic). Tests use `await loadAllGames()`
- **Loot** (`src/platform/rpg/items.ts`, `inventory.ts`):
  - items have a slot, a rarity from 0 (vanlig) to 4 (legendarisk), an item level and seeded stats (kraft, skydd, tur, visdom, snabbhet, klurighet)
  - chests are stored with a seed when found and opened later, so a reload never rerolls them
  - stats only affect boss damage (capped by `minHits`), hearts, crits, loot luck, XP % and hints per day
  - tamed bosses become unique pet items, and a Mästare drops their persona's `signatureItem`
  - the Smedjan (`#/smedjan`) has a shop, melting into azaleablad, and +1–+5 upgrades; items can also be melted (one, or all grey at once) straight from the backpack in Azaleagården
  - Azaleagården (`#/gard`) has tabs: Hjälten (the hero figure, tappable stats with `statExplain()`, equipment slots directly above the backpack, compare vs equipped), Garderoben, Kunskaper
  - **Path monsters** (`RunState.mob`, `MOB` in `balance.ts`, names in `src/content/monsters.ts`): stage runs only. Correct answers hit with gear damage (crit seeded from `seed + index`); a beaten monster gives azaleablad (not when tired) and the next one appears. It never changes run length, clearing or stars.
  - the boss intro shows the real hearts (`bossHearts`) and damage/hits (`bossPreview`)
- **Hero figure and cosmetics:** `src/shell/HeroFigure.tsx` draws an SVG body with the animal emoji as head; equipped gear is drawn by base id (`shapeOf`; colour = material tier from ilvl + rarity) and worn cosmetics on top. Cosmetics are in `src/platform/rpg/wardrobe.ts` (ids permanent; `cost` in kastanjer or an `unlock` from things that never go down: Mästare, level, best streak, arena rank, best storm steg, deepest cave floor), sold in Skräddaren (`#/skraddaren`, with try-on).
- **Mini-games** are paid with tokens (🎟️ `HeroState.polletter`, bought for 15 kastanjer in `arena.ts`, plus `ARENA.dailyTokens` when all daily quests are done; max 10). They pay azaleablad only, never kastanjer.
  - **Dimstormen** (`#/dimstormen`): a survivors-style action game. `src/platform/rpg/dimstorm.ts` (main chunk) turns gear into a `Loadout` (weapon base → attack type, skold slot → sköld/trollbok/lykta ability, pet, capped stat numbers) and saves results (`HeroState.storm`: highest open steg, wins, best won steg). The game itself is lazy-loaded: `src/minigames/dimstorm/sim.ts` is a pure, seeded simulation (`newGame`/`step`/`choose`, testable headless with a bot, see `tests/dimstorm.test.ts`) and `View.tsx` draws it on a canvas with the `HeroFigure` laid on top. 5 waves of 30 s + Stormjätten; in-run level-ups offer `UPS` cards. Leaving mid-storm still saves what was picked up.
  - **Grottdyket** (`#/grottdyket`): a turn-based roguelite dungeon on a 9×11 grid. `src/platform/rpg/grotta.ts` (main chunk) has `caveLoadout()` (weapon → melee/cleave/ranged/stun, sköld = block chance, trollbok = a spell every 8 turns, lykta = light radius, pet bites) and `finishCave()` (`HeroState.grotta`: deepest floor, dives). The lazy-loaded `src/minigames/grotta/sim.ts` is pure and seeded per floor (`newCave`/`act`/`descend`/`goHome`/`pathTo`); `View.tsx` is a DOM grid with fog of war, tap-to-walk (stops when something new shows up) and arrow keys. At each staircase the child picks deeper or home; falling (or leaving mid-floor) keeps half the blad. A boss guards every 5th floor. Tests: `tests/grottdyket.test.ts` (every floor connected over many seeds, each mechanic on a hand-built floor, a bot dive).
  - **Trasselvinden** (`#/trasselvinden`): untangle puzzles with monsters, in two modes (`KnutMode`, picked in the lobby; separate records `HeroState.trassel.best` / `.rep`). `src/platform/rpg/trassel.ts` (main chunk) has `knutLoadout()`/`knutNumbers()` (every stat has a job: kraft damage, snabbhet hit cooldown, tur crit + blad, skydd hp/armour, klurighet hints, visdom heal per knot; weapon/offhand/pet effects), `KNUT_MODES`, `knutBest()`, `knutResult()`, `finishKnut(hid, r, mode)` and `knutStarts()` (start points every 5 knots). The lazy-loaded game is in `src/minigames/trassel/`:
    - `strid.ts`: the shared part (monsters, combat, knot after knot, hints, rewards). A puzzle implements `Pussel` (`kvar`, `haller`, `slapp`, `spindelMal`/`trassla` for the spider, `knuff` for the hint, `bonus`); `newStrid(lo, seed, make, …)` runs it.
    - `sim.ts` = **Pinnknutar** (`PinnKnut`): drag pegs until no ropes cross. Knots are planar by construction (`makeKnot`: jittered grid + diagonals, `goal` = a solution), scrambled onto a circle; `crossings()` also counts a peg on a foreign rope.
    - `rep.ts` = **Repknutar** (`RepKnut`): coloured ropes with ends in holes, in layers (`z`). Only an uncovered rope can be lifted (`covered`); a moved rope goes on top (`flytta`). Solved = no two ropes touch (cross, or one lies over the other's end). Knots are built backwards from a tidy solved layout with `bakat()` steps, each the exact inverse of a legal move (the top rope moves an end, then is pushed down just below the lowest point where nothing covers it), so every knot is solvable in `par` moves (`losning`); the spider does the same step and raises `par`. Few moves (≤ par) give bonus blad.
    - `View.tsx` is one SVG (BW × BH units) with a frame shared by both modes and a layer per mode. Tests in `tests/trasselvinden.test.ts`.
  - Shared lobby bits (purse, buy-token row) are in `src/shell/Polletter.tsx`.
  - **Arenan = Bossduellen** (`#/arenan`): a real-time three-lane duel. `src/platform/rpg/arena.ts` (main chunk) holds tokens, `OPPONENTS` (order and names permanent: `HeroState.arena.rank` points into it; each has `moves`, `wind`, `open`), `MOVES` (which lanes a move hits), `duelLoadout()` and `winArena(hid, foe, flawless)` (saved after every win; a first win against the next opponent moves the rank, rematches pay 1–2 🌸). The lazy-loaded `src/minigames/duell/sim.ts` is pure (`newDuel`/`press`/`step`/`nextFoe`): the foe winds up (red lanes fill), the strike hits the lanes it shows, a dodge or a shield parry makes it dizzy, and only then do melee hits land (the bow chips a little). One token = an evening: opponent after opponent until a loss. Tests in `tests/arenan.test.ts` include bots (a masher never wins, a careful player does, gear helps a sloppy one).
- **Klassrummet** (`src/shell/Klassrum.tsx`, `src/platform/learning/lektioner.ts`): optional lessons beside the path. `AreaDef.lessons` holds `LessonMeta` (permanent `id`, title, `nodes` = stages/bosses it belongs to, shown before the first; optional `skills` for review runs and region bosses); the content is `GameModule.lessons[id]` (`Lesson` = pages with `text`, `pic`, `steps` revealed one by one, `tips`, `prova` = a real question spec, not recorded) in each game's `lektioner.tsx`, so it is lazy-loaded with the game. Picture primitives are in `src/engines/lektion/bilder.tsx`. Suggestions: `nudgeFor()` with `LEKTION` in `balance.ts` (mild > 20 % wrong, stark ≥ 50 %; stark = Mästare Kastanj asks once per run between questions). When a stage or boss run starts (index 0) and the node's lesson is unread, `PlayView` opens it by itself (`LessonLayer intro`, a "Hoppa över" bar; once per page visit via `visadeForeBanan`, so skipping doesn't nag; e2e `newHero` skips it with `addLocatorHandler`). In a run the lesson is a layer over the question (`LessonLayer`); never unmount the run's `View` for it, or the question could be answered twice. A new lesson needs content for its meta and vice versa (`tests/klassrum.test.ts` checks it). Lesson texts may show answers (they are worked examples, not the current question).
- **Introductions:** `HeroState.tips` + `markTip()`; Mästare Kastanj explains gear in Azaleabyn the first time a hero has an item or chest.
- **Tidstornet** (`src/games/klocka/`):
  - `logic/` holds the pure Swedish time-language model, the diagnosis of mistakes and the parser, ported from v0.1 and tested over all 720 times
  - `content.ts` holds the eras, stages, monster bosses (tamed → pets) and the final Mästare (persona via `personaFor`)
  - `V01_STAGE_MAP` maps the old v0.1 stage indexes
- **Learning loop** (`src/platform/learning/`): `events.ts` (the answer log), `skills.ts` (Leitner schedule per skill id, record `h:<id>:skills`; `noteAnswer` is called from `recordAnswer` and the free-practice labs; due skills = Glömskans dimma), `quests.ts` (daily quests, daily chest, streak with a weekly frysdag; `noteRun` is called by `PlayView` after `finishRun`). Skill names for the mentor are in `src/content/skills.ts` – a new skill id needs a label there (a test checks it). Every first answer goes through `learn()` in `progress.ts` (runs and free practice), which updates the schedule and grants **mastery**: when a skill reaches a higher box than ever before (`SkillItem.best`, never decreases; `bestBox()`), its area gets `MASTERY.xp[box]` kunskap XP – raw, never boosted by class or gear. Kunskap levels 5 and 10 grant the area's `kunskap.titles` (`grantKunskapTitles`, in `finishRun` and free practice); every area needs two unique titles (a test checks it). `solidCount()` (skills that ever reached box 4) drives the Kunskaper tab and the `sitter` wardrobe unlock.
- **Drill engine** (`src/engines/drill/`): for questions whose answer is a number typed into a box in an equation (or picked among choices). A game supplies `make / diagnose / explain / solution / hint` (+ optional `Visual`); `drillModule()` makes the `GameModule`. Explanations after a mistake explain the method and **never state the answer** (`tests/talbergen.test.ts` checks this), so the child fixes it themselves. It supports a prompt, units, multiple choice, fractions, decimals, negatives, an answer tolerance (`tol`) and a toolbox (`tools`: scratch pad, notes, formula card from `DrillGame.notes`, calculator; `Tools.tsx`). Used by all Talbergen areas except Tidstornet (`src/games/tiokompis/`, `tabeller/`, `pengar/`, `tallinje/`, `brak/`) and all Betongbukten parks (`src/games/geometri/<game>/`, shared SVG helpers in `geometri/draw.tsx`). Skill ids are by topic, not area: `ma.add.*`, `ma.sub.*`, `ma.mult.<n>`, `ma.div.<n>`, `ma.pengar.*`, `ma.tallinje.*`, `ma.avrunda.*`, `ma.negativa.*`, `ma.decimal.*`, `ma.brak.*`, `ma.geo.*`.
- **Ord engine** (`src/engines/ord/`): for questions whose answer is a word. Kinds: `val` (pick an option; each wrong `Alt` carries its error tag, `label` = button text; with a `sentence` containing `___` it is a gap, `fill` = what shows in the gap when done; `exact` = punctuation counts), `skriv` (hear and type; needs a Swedish voice, otherwise or after "Hör du inget?" it falls back to `val` with `q.alts`), `markera` (tap a word, `targets`; `misses` = error tag per wrong word, `OrdGame.explainMiss` for the explanation, `mark` = the comma/full stop shown after the right word when done), `ordna` (tap `tiles` into a line before `end`; `answers` = other accepted orders; shown after 3 tries). A game supplies `make / diagnose / explain / solution / hint`; `ordModule()` makes the `GameModule`. Typed answers ignore case unless `caseStrict`, and a trailing full stop. The answer box has spellcheck/autocorrect/autocapitalize off (autocorrect is set as an **attribute** via a ref: Preact would set the property, and `"off"` is truthy); on touch devices the in-app keyboard (`Tangentbord.tsx`) replaces the device keyboard, which would autocorrect the spelling. Explanations and hints never contain the answer: `explainAny`/`hintFor` mask it as a safety net, and game texts avoid it with `avoid()` (small words like "och", "det", "med" are themselves answers). `deckPick()` uses the run's `QuestionCtx` (`{ seed, index }`, passed to `makeQuestion` by `currentQuestion`) so a run never repeats a word. Speech lives in `src/platform/speech.ts` (`voices` signal, `voiceFor` prefers on-device voices, `hasVoice`); Vuxenläge has "Testa uppläsning" and voice install guides.
- **Stavningsträsket** (`src/games/stavning/`, Ordskogen): word lists per spelling rule in `ord.ts` (`[word, sentence, band, misspellings?]`; band 2 = åk 3–4+; compounds as `glass|bil`), `logic.ts` generates typical misspellings per rule (like klocka's `candidates()`) which become both the wrong options and the diagnosis. Levels: 0 choose, 1 dictation, 2 dictation with harder words, 3 find the misspelled word. Skill ids `sv.stav.<rule>`. Tests in `tests/stavning.test.ts` (every word fits its rule and sentence, every trap can trigger, no explanation reveals the answer) and `e2e/stavning.spec.ts` (fake voice via `addInitScript`).
- **Rimbäcken** (`src/games/rim/`, Ordskogen): content in `ord.ts` (rhyme groups by rime, verses, word pairs `[word, synonym, antonym, related]`, compounds, homonyms, idioms; band 1/2), `logic.ts` turns a mode + level into topics (`rim`/`vers`, `motsats`, `synonym`, `sammansatt`/`ordet`, `betydelse`, `uttryck`) and builds `val` questions whose wrong options carry the tags. Skill ids `sv.ord.<topic>`.
- **Meningssmedjan** (`src/games/mening/`, Ordskogen): content in `meningar.ts`. `BYGG` sentences are chunks with roles (S, V, N, M, O, A, Q); `orders()` derives every accepted order (verb second; S/O/A may lead; trailing adverbials permute; wh- and yes/no questions) and `diagnoseOrder()` tags mistakes. Names in sentences must be in `NAMN` (the only capitals mid-sentence). Skill ids `sv.mening.<topic>`.
- **Ordklassernas tempel** (`src/games/ordklass/`, Ordskogen): content in `ord.ts`. `MENINGAR` are annotated (`"Katten:s sover:v på:r …"`; s/v/a/p/r, x = never asked); `markera` counts every word of the asked class. Nouns, verbs (strong ones carry their typical wrong form, e.g. `gådde`), adjectives to compare and pronoun sentences are tables; wrong options are built from them. Skill ids `sv.ordklass.<klass>` and `sv.bojn.<topic>`. Prompts avoid small words that can be answers (no "Tryck på …").
- **Berättelsebiblioteket** (`src/games/berattelse/`, Ordskogen): texts with their questions in `texter.ts` (each question = right answer + two wrong ones with tags; band 1 = short). The text is the game's `Visual`; `deck()` keeps a run's questions about one text together. Texttyp questions are generated from `Text.typ`. Skill ids `sv.las.<topic>`. Region boss **Ordskogens hjärta** is `src/games/ordskogen.ts`.
- **Ön växer** (`src/platform/rpg/vaxt.ts`, drawings in `src/shell/IslandGrowth.tsx`): each region on the map gains detail at 4 steps (first stage, first Mästare, three Mästare, region boss), counted only from things that never go back; `HeroState.oSteg` remembers what the hero has seen so a new layer pops in once.
- **Västerön (engelska)** (five areas + region boss `src/games/vasteron.ts`, persona `vasteron.region`): all on the ord engine, which has `OrdQ.lang` (`'en-GB'`: 🔊/dictation use that voice, the in-app keyboard drops åäö), `listen` (a hear-and-choose question: `say` plays at once and isn't shown; without a voice for the language `read` is shown instead), `pic`/`Alt.pic` (emoji or a `#rrggbb` colour swatch; picture choices) and an optional per-game `Visual`. Skill ids are per theme/topic, never per word: `en.glosor.*`, `en.lyssna.*`, `en.tid.*`, `en.stav.*`, `en.gram.*`. Instructions stay Swedish; English content is English. Shared checks for every ord game are in `tests/ordcheck.ts` (one right answer, unique options, explanations/hints never contain the answer).
  - **Glosviken** (`src/games/glosor/`): themed words `[en, sv, pic, band]` in `ord.ts`, look-alikes (`LIKNAR`, Tvillingkrabban) and false friends (`FALSKA`, Falska Fröken Friend). The deck is word × question type (picture → word, hear → picture, sv → en, en → sv).
  - **Hamnen** (`src/games/hamnen/`): listening – numbers (teen/ty, Ekomåsen), letter names and words spelled aloud (Papegojan Alfa), phrases, classroom instructions, questions → answers, generated sentences. Number words in `src/games/engelska/tal.ts`.
  - **Big Ben-tornet** (`src/games/bigben/`): English time (`phrase`, `digitalPhrase`, `ampmPhrase`), klocka's `ClockFace` as the visual. Traps `half-past` (half past three ≠ halv tre) and `past-to`.
  - **Stavklippan** (`src/games/stavklippan/`): English spelling rules; `variants()` generates typical misspellings (Swedish-style `som-svenska`, silent letters, magic e …) used for options and for diagnosing dictation.
  - **Piratskeppet** (`src/games/pirat/`): a/an, am/is/are, plural, -s, question words, prepositions (drawn scene), don't/doesn't, word order (choose, or build with tiles; Swedish V2 order is diagnosed as `svensk-ordfoljd`).
- **Robotön (programmering)** (region boss `src/games/roboton.ts`, persona `roboton.region`). Skill ids `prog.<logik|kod|loop|bugg|py>.*`.
  - **Robot engine** (`src/engines/robot/`): `world.ts` is pure: `run(world, prog)` → trace (states with block ids like `'2.0'`, crash, gems), `solves`, `solve` (BFS shortest program for a palette), and program edits (`replaceAt`, `swapLR`, `loopCounts`, `firstOnly`, `stepOff` …). `gen.ts` builds worlds (`puzzle`, `patternWorld`), vart spots from misconceptions (`wrongEnds`/`vartSpots`), bugs (`injectBug`, `fixable` = every block where one edit fixes it counts as right) and lucka fills (exactly one works). `check.ts` diagnoses a built program by trying small edits (`diagnoseProg`) and owns the explanations (`ROBOT_ERR`). `RobotView.tsx` draws the grid, animates runs (reduced motion jumps) and has the block editor (cursor into an open loop). Kinds: `bygg`, `vart`, `bugg`, `lucka`. `robotModule()` makes the GameModule.

Kinds in `logic.ts`: `gor` (follow a program move by move; a wrong move is shown and undone, then diagnosed `prim`/`motsatt-sida`/`fel-sida`/`dubbel`), `vilket`, `bit` (tap a sticker), `losa` (turn freely until `klart()` = goal reached and nothing solved broken; `Klar!` diagnoses, a move budget, "Visa lösningen" after 2 misses; `hela` = a whole solve with step name and "Nästa drag", lesson only), `valj`.
